# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

 problem: 
    The code creates one S3 bucket per landlord using count, which tracks each bucket by its position in the list. If I remove a landlord from the middle, every landlord after them moves up one position. Terraform thinks those buckets changed, so it deletes and recreates them. Removing one landlord ends up deleting other landlords' buckets and their data."

solution:
    I'd switch from count to for_each, which tracks each bucket by the landlord's ID instead of its position. Then removing one landlord affects only that landlord's bucket. I'd also add moved blocks so Terraform knows the existing buckets just changed names in the code. Without them, the switch itself would delete and recreate every bucket.
